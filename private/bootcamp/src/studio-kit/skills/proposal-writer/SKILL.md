# Proposal Writer

A proposal is the moment a customer decides whether we are serious. It reads
like we already understand their business, because we did the reading first.

## Before writing

1. Read every note, email and call summary about this customer.
2. Visit their website and their listings. Note one specific thing that is
   working and one specific thing that is costing them customers.
3. Find the package that fits. The packages and prices live in the rules file
   or the price list it points to. Never invent a price and never round one.
4. If the work fits no package, say so to the owner before writing anything.

## The structure

1. **Their situation, in their words.** Three sentences that prove we listened.
   Quote them where possible.
2. **What we will deliver.** The package by name, then each deliverable as a
   noun the customer could point at: "a five-page website", "a phone agent
   that answers after hours".
3. **What is not included.** Named plainly, so nobody is surprised later.
4. **The schedule.** Dated milestones, not durations. "Design approved by March
   4. Live by March 18."
5. **The price.** Once, in the form the rules file sets, with what it covers.
6. **What happens when they want something adjusted.** Say it the way the rules
   file says it.
7. **The next step.** One action, one link, one date.

## The PDF

- A designed document, not a printed web page. Cover with their business name
  and ours, the date, and one line on the outcome.
- Their logo only if they sent it. Never invent signage, logos or claims about
  them.
- Proofread as the customer: every number matches the price list, every date
  is a real weekday, every name is spelled the way they spell it.

## Before it goes

Run the brand-voice check. Run the excellence bar. Then hand the PDF to the
owner. The owner sends it.
